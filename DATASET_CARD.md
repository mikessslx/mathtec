# MathTEC-Bench — dataset card

A synthetic benchmark for sentence-level correction of mathematical text that mixes English prose with inline LaTeX. Each sample pairs a clean statement with a corrupted variant produced by rule-based error injection.

- **File:** `data/mathtec_bench.json` (~370 KB, included in this repository)
- **Samples:** 500 (441 with at least one injected error, 59 clean)
- **Injected errors:** 745
- **License:** [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)
- **Paper:** [MathTEC: A Multi-Agent Framework for Mathematical Text Error Correction](https://doi.org/10.1109/ICCCS69761.2026.11613421) — ICCCS 2026 (IEEE)

## Schema

The file is a JSON object with two top-level keys:

| Key | Contents |
|---|---|
| `metadata` | name, version, sample count, generator config (seed, error weights, clean ratio), summary statistics |
| `data` | list of 500 sample objects |

Each sample:

| Field | Type | Description |
|---|---|---|
| `id` | int | 0-based index, contiguous |
| `original` | str | Clean reference statement, the correction target |
| `corrupted` | str | Noisy input given to the system |
| `errors` | list | Injected edits: `type`, `original`, `corrupted`, `start`, `end` |
| `num_errors` | int | Number of injected errors (0 for clean samples) |
| `error_types` | list | Unique error types present in this sample |

## Error types

| Type | Description | Occurrences |
|---|---|---|
| `spelling` | Misspelled mathematical terminology, e.g. `funciton` | 221 (29.7%) |
| `ocr_symbol` | Symbol/command confusion, e.g. `\theta` → `0` | 175 (23.5%) |
| `ocr_formula` | Structural LaTeX corruption, e.g. `\mathbb{R}` → `R` | 77 (10.3%) |
| `variable` | A repeated variable replaced by another valid symbol | 38 (5.1%) |
| `handwriting_confusion` | Visually similar characters outside math spans, e.g. `o`↔`0` | 234 (31.4%) |

## Construction

1. **Clean statements.** Generated by prompting GPT-5.4 for short, self-contained, mathematically correct English statements with inline LaTeX, across 10 topics (calculus, linear algebra, probability/statistics, real analysis, abstract algebra, number theory, differential equations, topology, discrete mathematics, optimization). Deduplicated by exact match after whitespace normalisation.
2. **Corruption.** Rule-based injection by `data/error_injector.py`, seeded (`seed: 42` in the metadata), with the documented weights and 1–3 errors per sample plus a ~10% clean-sample ratio.
3. **Selection.** The builder selects corrupted examples and retains a clean subset for over-correction evaluation. Clean examples may be formed by reverting selected corruptions or by retaining statements for which error injection made no change.

Generation is performed by `data/construct_benchmark.py`. A separate source-text cache is not shipped; the clean reference statements are included in the benchmark as the `original` field.

## Known limitations

- **Synthetic.** Both the clean statements and the corruptions are machine-generated. Performance on this benchmark does not establish robustness on real scanned documents or human-authored OCR output.
- **No topic labels.** Although the statements span 10 topics, the released JSON stores no per-sample topic field, so per-topic analysis is not possible from the file alone. This is acknowledged in the paper's Limitations section.
- **Realised error mix ≠ nominal weights.** Nominal weights are spelling 0.25, OCR-symbol 0.25, OCR-formula 0.20, variable 0.05, handwriting 0.25. Injection is not retried when a sentence offers no valid site, and measured per-type success rates are approximately spelling 97%, OCR-symbol 72%, OCR-formula 41%, variable 72%, handwriting 100%. Consequently OCR-formula contributes 10.3% of realised errors instead of 20%, and 745 of 1000 nominal draws resulted in an error.
- **One duplicated statement.** 500 samples contain 499 distinct `original` strings.
- **Surface-form evaluation.** The benchmark does not encode mathematical equivalence. The evaluation scripts compare surface forms, so mathematically equivalent rephrasings can still count as mismatches.

## Intended use

Evaluating conservative correction of noisy mathematical text. The clean-sample subset is intended to measure **over-correction** — a system that rewrites text it should have left alone scores badly on those 59 samples.

## Out of scope / prohibited use

- Do not treat benchmark scores as evidence of performance on genuine OCR corpora.
- The statements were generated using a proprietary LLM API; downstream use should respect that provider's terms of service.
